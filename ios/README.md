# Kioku for iOS

The unmodified Anki desktop app (`aqt` 26.8.1) running natively on iPhone and
iPad: no emulator, VM or Linux userland.

- **Python 3.14** from [BeeWare's Python-Apple-support](https://github.com/beeware/Python-Apple-support),
  embedded by `src/main.mm`.
- **Qt 6.11 for iOS** (static) and **PyQt6 6.11**, whose binding sources are
  generated by sip and compiled into the app as static libraries.
- **Anki's Rust core** (`rsbridge`), **orjson** and **rpds-py** built for
  `aarch64-apple-ios` as static libraries; all native modules are registered
  as built-in modules, so iOS never loads code it didn't sign.
- **Qt WebEngine** does not exist on iOS: the `PyQt6.QtWebEngine*` modules are
  replaced by `shared/python` on top of **WKWebView**
  (`python/kioku_platform/webview.py`, through rubicon-objc).
- Phone adaptations shared with the native Android variant live in
  `shared/python/kioku/` (window fitting, patches, media server watchdog);
  iOS-specific ones in `python/kioku_platform/`.

Anki's data is in the app's Documents folder (`Anki2/`), visible in the Files
app, where exports also go (`Exports/`).

See [../docs/fixes.md](../docs/fixes.md) for every problem met on the way and
[../docs/testing.md](../docs/testing.md) for what has been tested.

## Building

Requirements: macOS with Xcode, [uv](https://docs.astral.sh/uv/), rustup,
`protoc` (`brew install protobuf`), SWIG (`brew install swig`, for PyMuPDF),
about 20 GB of disk.

```sh
cd ios
tools/build.sh                       # unsigned: build/Kioku-<version>-unsigned.ipa
KIOKU_TEAM=<team id> tools/build.sh  # signed for your devices (Xcode account)
```

`tools/build.sh` runs, in order: `fetch_deps.sh` (Qt, Python, Anki source,
PyQt6/sip and other sources into `deps/`), `build_rust.sh`, `gen_pyqt.sh`,
`../shared/tools/prepare_site.sh`, `../shared/tools/build_pymupdf.sh` (MuPDF
and PyMuPDF into `../build/pymupdf/`), then CMake (Xcode generator) and
`xcodebuild`. Versions come from `../shared/versions.env`.

The unsigned `.ipa` can be installed with a sideloading tool that re-signs
apps (AltStore, Sideloadly, …).

## TestFlight

Kioku is distributed through TestFlight ([signup form](https://forms.gle/fw4YMTdGbgD8nqPe8)), not the App Store.

```sh
KIOKU_TEAM=<team id> tools/testflight.sh                # build, archive, upload
KIOKU_TEAM=<team id> tools/testflight.sh --upload-only  # upload the last archive
uv run --with 'pyjwt[crypto]' python tools/appstore_metadata.py  # texts in appstore/
```

Needs an App Store Connect API key (`APP_STORE_KEY_ID` and
`APP_STORE_ISSUER_ID` in `../.env`, `AuthKey_<key id>.p8` at the repo root,
both gitignored) and either an **Apple Distribution** certificate in the
keychain or a key with the Admin role (cloud-managed signing). The build
number is the commit count; it must grow with every upload. Builds expire
90 days after upload.

## Developing on a device

```sh
KIOKU_TEAM=<team id> tools/run_device.sh       # build, install, launch, show the log
tools/devcmd.sh --shot 'print(widgets())'      # run Python in the app, take a screenshot
tools/sweep.sh                                 # open every window, report overflow
tools/smoke.sh                                 # crash sweep: windows, study, switch profile, Back
```

## Developing on the Simulator

```sh
tools/run_sim.sh                         # build, install, launch, show the log
KIOKU_SIM="iPhone 16 Pro" tools/run_sim.sh   # pick a simulator (name or UDID)
```

Qt's prebuilt iOS libraries have no arm64 simulator slice, so the first run
builds Qt (qtbase + qtsvg) from source into `deps/qt/<ver>/iossim`
(`tools/build_qt_sim.sh`, ~20 min); later runs reuse it. The app goes to
`build/xcode-sim`, separate from the device build. The simulator sets no
`USER`, so `run_sim.sh` launches with `USER=mobile` (Anki's `getpass.getuser()`
needs it). `devcmd.sh`, `sweep.sh` and `smoke.sh` only talk to a device.
Audio, TTS and WebKit media behave differently from a phone: check those on a
device.
